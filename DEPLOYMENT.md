# MassUp AI 1.0.4 — состояние проверки

Исходная ветка: `main`, коммит `964ebe7` (1.0.3). Обновление 1.0.3 было
отправлено на GitHub, но испортило русскую кодировку HTML. В 1.0.4 текст
восстановлен из сохранённого исходника; ссылки на ресурсы обновлены.

## Что исправлено

- Uvicorn единолично обрабатывает сигналы процесса; polling не заменяет его обработчики.
- Каждый запуск получает отдельный Router; завершение polling отражается в журнале.
- «Сегодня» определяет дату при запросе, а не при импорте.
- Запись исторического веса не заменяет актуальный вес в профиле.
- Вес без профиля и будущая дата возвращают понятную ошибку.
- Ошибки AI не раскрывают исходное сообщение исключения в HTTP-ответах и журнале приложения.
- HTTP-клиент AI закрывается после запроса; ожидание и повторные попытки ограничены.
- Закрытие диалога не отправляет форму; повторное нажатие записи веса блокируется на время запроса.
- HTML/API не кешируются; статические ресурсы проходят проверку актуальности.
- В Docker добавлены проверка импортов и локальная проверка здоровья.

## Диагностика BotHost

Требования: `HOST=0.0.0.0`, `PORT=8000`, внутренний порт панели `8000`,
собственный Dockerfile. Секреты — только в переменных окружения сервера.
Путь к существующей базе не менять; `.env` и данные этим обновлением не заменяются.

После запуска должна появиться строка:

```text
MASSUP_START version=1.0.4 bind=0.0.0.0:8000
LOCAL_HTTP_OK version=1.0.4 port=8000 status=200
```

Первая строка подтверждает конфигурацию, вторая — ответ HTTP внутри контейнера.
Они НЕ подтверждают работу внешнего домена. `/health` показывает версию,
состояние чтения БД и активность задачи polling. `bot_polling=active` не доказывает,
что Telegram успешно авторизовал бота. `ai_configured=true` означает только наличие ключа.

Если внутренний HTTP отвечает, а публичный домен — 502, необходимо проверить
маршрут Traefik до конкретного контейнера, его сетевую доступность и выбранный
порт на стороне BotHost. Нельзя считать это доказанной неисправностью платформы
без такой проверки. Проект пересоздавать наугад не нужно.

## Проверено локально

`python -m pytest -q`: 22 теста, включая повторное открытие SQLite приложением,
обновление веса за один день, исторический вес, смену суток, безопасный ответ на
имитированный OpenAI 401, меню/фото с подменённым AI, кнопку /start и завершение polling.

`node --check web/app.js`, `node --test tests/test_frontend.cjs`: 5 JS-тестов.
Проверены число и дата веса, высота/ограничение ширины столбика, пустая история,
ошибка сохранения и повторная попытка. Это проверки кода с заменителями DOM,
а НЕ визуальная проверка в Telegram.

`python -m compileall -q app run.py scripts tests` и `git diff --check` проходят.
В отдельном локальном запуске внутренняя самопроверка HTTP вернула 200.
Проверка из другого сеанса команд завершилась URLError; причину изоляции сеансов
ещё необходимо проверить. Docker daemon недоступен, сборка образа не проверена.

## Не выполнено / следующий шаг

- GitHub читается, но push требует отсутствующую авторизацию. Локальный коммит подготовлен.
- Прямой запрос BotHost остановлен ограничением доступа; публичный 502 ещё не диагностирован.
- Браузер заблокировал локальную страницу (`ERR_BLOCKED_BY_CLIENT`); визуальная проверка не выполнена.
- Не подтверждены: деплой 1.0.4, публичный HTTP 200, сохранность диска BotHost после рестарта,
  действующий API-ключ и реальная генерация плана в Telegram.
- Продолжать с этих проверок; не объявлять production готовым по локальным тестам.
