# MassUp AI 1.0.4 — состояние проверки

Исходная ветка: `main`, коммит `964ebe7` (1.0.3). Обновление 1.0.3 было
отправлено на GitHub, но испортило русскую кодировку HTML. В 1.0.4 текст
восстановлен из сохранённого исходника; ссылки на ресурсы обновлены.

## Что исправлено

- Uvicorn единолично обрабатывает сигналы процесса; polling не заменяет его обработчики.
- Каждый запуск получает отдельный Router; завершение polling отражается в журнале.
- «Сегодня» определяет дату при запросе, а не при импорте.
- Запись исторического веса не заменяет актуальный вес в профиле.
- Вес без профиля и будущая дата возвращают понятную ошибку.
- Ошибки AI не раскрывают исходное сообщение исключения в HTTP-ответах и журнале приложения.
- HTTP-клиент AI закрывается после запроса; ожидание и повторные попытки ограничены.
- Закрытие диалога не отправляет форму; повторное нажатие записи веса блокируется на время запроса.
- HTML/API не кешируются; статические ресурсы проходят проверку актуальности.
- В Docker добавлены проверка импортов и локальная проверка здоровья.

## Диагностика BotHost

Требования: `HOST=0.0.0.0`, `PORT=8000`, внутренний порт панели `8000`,
собственный Dockerfile. Секреты — только в переменных окружения сервера.
Путь к существующей базе не менять; `.env` и данные этим обновлением не заменяются.

После запуска должна появиться строка:

```text
MASSUP_START version=1.0.4 bind=0.0.0.0:8000
LOCAL_HTTP_OK version=1.0.4 port=8000 status=200
```

Первая строка подтверждает конфигурацию, вторая — ответ HTTP внутри контейнера.
Они НЕ подтверждают работу внешнего домена. `/health` показывает версию,
состояние чтения БД и активность задачи polling. `bot_polling=active` не доказывает,
что Telegram успешно авторизовал бота. `ai_configured=true` означает только наличие ключа.

Если внутренний HTTP отвечает, а публичный домен — 502, необходимо проверить
маршрут Traefik до конкретного контейнера, его сетевую доступность и выбранный
порт на стороне BotHost. Нельзя считать это доказанной неисправностью платформы
без такой проверки. Проект пересоздавать наугад не нужно.

Документация:
- https://bothost.ru/docs/web-apps-domains
- https://bothost.ru/docs/custom-dockerfile
- https://developers.openai.com/api/docs/guides/error-codes

## Проверено локально

`python -m pytest -q`: 22 теста, включая повторное открытие SQLite приложением,
обновление веса за один день, исторический вес, смену суток, безопасный ответ на
имитированный OpenAI 401, меню/фото с подменённым AI, кнопку /start и завершение polling.

`node --check web/app.js`, `node --test tests/test_frontend.cjs`: 5 JS-тестов.
Проверены число и дата веса, высота/ограничение ширины столбика, пустая история,
ошибка сохранения и повторная попытка. Это проверки кода с заменителями DOM,
а НЕ визуальная проверка в Telegram.

`python -m compileall -q app run.py scripts tests` и `git diff --check` проходят.
В отдельном локальном запуске внутренняя самопроверка HTTP вернула 200.
Проверка из другого сеанса команд завершилась URLError; причину изоляции сеансов
ещё необходимо проверить. Docker daemon недоступен, сборка образа не проверена.

После паузы временное Python-окружение было удалено; повторная установка зависимостей
остановлена отменой сетевого доступа. Добавлен `tests/test_runtime.py` для проверки
HTTP, записи веса и остановки/повторного запуска настоящего процесса. Этот новый
тест ещё НЕ запускался; число 22 выше относится к предыдущему подтверждённому прогону.
На Windows тест пропускается, поскольку завершение процесса отличается от SIGTERM.

## Обновление 1.0.5

Сборка образа 1.0.4 завершилась успешно и включала новые команды Dockerfile,
но runtime-журнал продолжил показывать старый код без строки `MASSUP_START`.
Это соответствует описанному BotHost bind mount каталога `/app`: содержимое образа
в `/app` скрывается источниками, которые платформа монтирует при запуске.

Рабочий каталог и код перенесены в `/usr/src/massup`, вне mount. Постоянная база
остаётся в `/app/data/nutrition.db`. Внешняя переменная `DATABASE_PATH`, если она
задана в панели, по-прежнему имеет приоритет над значением Dockerfile.

## Обновление 1.0.6

Добавлена команда владельца `/backup`. Она создаёт согласованный снимок SQLite
через API резервного копирования и отправляет файл владельцу в Telegram. Команда
работает только при заданном `OWNER_TELEGRAM_ID` и не передаёт базу другим пользователям.

## Обновление 1.0.7

Добавлено защищённое восстановление базы без файлового менеджера BotHost. Владелец
прикрепляет сохранённый `nutrition.db` к сообщению Telegram с подписью `/restore`.
Бот принимает команду только от `OWNER_TELEGRAM_ID`, ограничивает размер файла,
проверяет целостность SQLite и наличие таблиц MassUp AI. Перед заменой создаётся
временный откат; при любой ошибке рабочая база сохраняется. После успешного
восстановления нужно проверить `/today`, затем открыть Mini App через новый `/start`.

Для нового проекта BotHost домен проверен с внутренним портом `3000`. Перед
переключением polling нужно остановить старый проект, установить в новом
`PORT=3000`, новый `WEBAPP_URL` и `RUN_BOT=true`, а затем перезапустить его.

## Обновление 1.0.8

Добавлен отдельный флаг `PUBLIC_ACCESS`. При `PUBLIC_ACCESS=true` обычные команды
бота и Mini App доступны всем пользователям с подтверждённой Telegram-подписью.
Данные по-прежнему изолированы по Telegram ID. `OWNER_TELEGRAM_ID` сохраняется:
команды `/backup` и `/restore` проверяют его независимо и остаются закрытыми.
AI-функции работают без пользовательских суточных лимитов.

## Обновление 1.1.0

Добавлена вкладка «AI-тренер» с шестью режимами: умный добор дневной нормы,
разбор рациона, рецепт из продуктов дома, замена блюда, пересчёт порции и
персональный вопрос тренеру. Сканер этикетки считывает видимые КБЖУ, состав и
аллергены, не подставляя неизвестные цифры.

Локальная аналитика показывает серию дней, достижения, отчёт за 7 дней и
осторожный прогноз достижения цели по истории веса. Она не расходует OpenAI API.
Пользователь может добровольно включить напоминания о завтраке, обеде, вечернем
остатке, еженедельном взвешивании и воскресном отчёте. Часовой пояс берётся из
Telegram Mini App; отметки об отправке хранятся в SQLite и защищают от дублей
после перезапуска контейнера.

Миграция создаёт только новые таблицы `reminder_settings` и `reminder_log` через
`CREATE TABLE IF NOT EXISTS`. Профили, питание, вес, планы и секреты не изменяются.
Для часовых поясов Windows/Docker добавлена зависимость `tzdata`.
